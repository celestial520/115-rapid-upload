# 115秒传助手

监控本地目录，文件落进来后先验证 115 能不能**秒传**：

- 能秒传 → 在 115 网盘创建文件 → 企业微信通知 →（可选）通知 CMS 增量同步 → 按设置删除/保留本地文件
- 不能秒传 → 原样拦截，不占带宽，等到**第二天设定的时间**再验证一次，直到能秒传为止

只做秒传，**不做真实上传**。115 上没有相同内容的资源会一直等着，不会偷偷把几十 G 传上去。

自带 WebUI（默认端口 `9191`），扫码授权、改配置、看状态都在网页里完成。

## 快速开始

### 1. 准备目录

假设你的下载目录是 `/volume1/115`（群晖/NAS 常见路径），先建好数据目录：

```bash
mkdir -p /volume1/docker/115-rapid/config
```

### 2. 启动

```bash
mkdir -p /volume1/docker/115-rapid && cd /volume1/docker/115-rapid
# 把本仓库的 docker-compose.yml 放到这个目录，然后：
docker compose up -d
```

镜像已发布，直接拉：

```
ghcr.io/celestial520/115-rapid-upload:latest    （linux/amd64 + linux/arm64）
```

`docker-compose.yml` 里唯一需要改的是挂载路径：

```yaml
    volumes:
      - ./config:/config
      - /volume1/115:/watch     # 左边改成你自己的下载目录
```

打开 `http://你的NAS地址:9191`。

> 镜像拉不动 / 想自己编：把 compose 里 `image:` 注释掉、打开 `build: .`，
> 执行 `docker compose up -d --build`，首次构建约 1~2 分钟。

### 3. 登录

第一次打开 `http://NAS地址:9191` 会跳到登录页：

```
账号：admin
密码：admin
```

登录后到「设置 → 账号密码」里改掉，别一直用默认密码。

### 4. 网页里配三件事

1. 点右上角 **扫码登录 115**，用手机 115 App 扫（二维码有效期约 2 分钟，过期点「刷新二维码」）
2. **设置 → 监控任务** 里点「+ 添加监控任务」，一行填一组：
   - 任务名（随意，比如「电影」）
   - 本地监控目录（点「浏览」选容器里的目录，或直接填 `/watch/movies`）
   - 115 目标目录（点「浏览」列网盘文件夹，或直接填 `/电影`）
   - 想加几个就点几次「+ 添加监控任务」，每个任务互不影响
3. 保存 → 点 **立即运行一次** 验证链路

## 配置说明

### 基础

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用 | 开 | 关掉后不再扫描（网页仍可手动运行） |
| 监控任务 | 空 | 多组「本地目录 → 115 目录」，在「设置 → 监控任务」里增删；每组可单独设置启用、保留源文件、CMS 通知 |

| 每天几点扫描 | 09:00 | 全量扫描的时间 |

| 配置 | 默认 | 说明 |

| 第二天几点再检测 | 09:00 | 秒传失败后，统一在**次日这个时刻**重试 |
| 每天清理空文件夹 | 开 | 只删空目录；监控目录本身永远保留 |

## 下载器监控（Transmission）

不想等扫描？让下载器直接通知：**Transmission 任务一完成，就立刻处理这个任务的文件/文件夹**。

| 配置 | 说明 |
|---|---|
| 启用 | 打开后才会轮询下载器 |
| 地址 | 形如 `http://192.168.1.10:9091`（Transmission 的 Web 端口） |
| 用户名 / 密码 | 下载器开了认证就填，没开留空 |
| 查询间隔（秒） | 默认 30。只是发一个 RPC 问状态，不读写磁盘 |
| 路径映射 | 把下载器里的路径翻译成容器里的路径，见下 |

### 为什么要路径映射

Transmission 和本工具通常是两个容器，同一块硬盘挂的位置不一样：

```
Transmission 看到：/downloads/蜘蛛侠/第一集.mkv
本工具看到：      /watch/蜘蛛侠/第一集.mkv
```

填一对映射（`/downloads` → `/watch`）就行。两边路径一样就不用填。

### 它是怎么判断"完成"的

通过 Transmission 官方 RPC（`/transmission/rpc`）拉任务列表，看 `percentDone == 1` / `isFinished` / 状态为已完成。
**还没下完的任务一律不碰**，任务报错的也跳过。已经处理过的任务按 hash 记住，不会重复触发。

单文件和整文件夹都支持：

```
任务「蜘蛛侠」完成（目录）      → 处理 蜘蛛侠/ 下所有文件
任务「某电影.mkv」完成（单文件） → 只处理这一个文件
```

### 装了下载器监控之后

日常流程就是：**下完 → 立即秒传**，中间的扫描完全不用管。
「每天定时全量扫描」留着当保险就行（默认每天 09:00 一次）。

## 外部触发（给 MoviePilot 插件用）

MoviePilot 整理完成后，可以用配套插件把文件路径**直接推过来**，立刻尝试秒传，不用等每日扫描。

### 在助手里拿配置

「设置 → 外部触发」里有一个 **API Key**（首次启动自动生成，可复制、可重置）。
把这三样填到 MP 插件里：

| 项 | 例子 |
|---|---|
| 助手地址 | `http://192.168.1.10:9191` |
| API Key | 网页上复制 |
| 路径映射 | `/media => /watch`（MP 容器路径 → 助手容器路径） |

### 接口

```http
POST /api/trigger
X-API-Key: <你的 Key>
{"paths": ["/watch/电影/蜘蛛侠 (2026)/蜘蛛侠.mkv"]}
```

- 接受文件和目录；目录会展开成里面的文件
- 路径必须落在某个监控任务的 `watch_dir` 里，否则跳过并在 `skipped` 里说明原因
- 立刻进入秒传流程，接口本身不阻塞

```http
GET /api/ping
X-API-Key: <你的 Key>
→ {"ok": true, "version": "1.0", "tasks": [...]}
```

用来确认地址/Key 是否正确、助手当前配了哪些监控目录。

## 每个监控目录都支持所有触发源

不用管"这个目录该由谁来触发"——**每条任务都会被三种来源共同覆盖**，
文件落在哪个监控目录里，就按那条任务的目标目录去秒传：

```
/9kg（TR 下载目录，不整理）        → 任务「下载」→ 115 /下载
/watch（MP 整理后的媒体库）        → 任务「媒体库」→ 115 /电影
/任何你新加的目录                  → 新建一条任务，一样能用
```

触发时按**路径归属**分发：TR 说"这个任务下完了，文件在 `/9kg/蜘蛛侠`"，
助手就去匹配哪条任务的 `watch_dir` 包含这个路径，交给那条任务处理。

文件列表里有一列「**来源**」，能看出这个文件是被谁触发的：

| 来源 | 含义 |
|---|---|
| `TR 完成` | Transmission 任务下载完成主动通知 |
| `MP 整理` | MoviePilot 插件整理完成后推过来的 |
| `文件变化` | inotify 发现有新文件 |
| `每日扫描` | 每天定时全量扫描发现 |
| `手动` | 点了「立即运行一次」 |

如果 TR 有已完成的任务却"没匹配到监控目录"，页面会直接提示是哪个任务、哪个路径、
以及原因（路径映射不对 / 不在任何监控目录里），方便排查。

## 触发方式：不扫盘，只在需要时干活

没有周期性扫盘。只有三种情况会去处理文件：

| 优先级 | 触发 | 什么时候发生 |
|---|---|---|
| 1 | **下载器监控** | Transmission 任务一完成，立刻处理这个任务的文件/文件夹 |
| 2 | **文件变化实时触发** | 监控目录里有文件被创建/移动进来（inotify，内核通知，不读盘） |
| 3 | **每天定时全量扫描** | 到点把监控目录扫一遍，兜住"从别处拷进来""容器重启"这类情况，顺手重试上次失败的 |

前两种是实时的，通常下载完几十秒内就处理完；第三种是保险，一天一次，时间自己定。

### 关于"正在下载的文件"

不会被误传，有两道关：

1. 下载器监控只认**已完成**的任务（`percentDone == 1`），没下完的不碰
2. 文件事件和每日扫描会检查**文件写入静置**（默认 30 秒）+ 连续两次大小/修改时间一致
3. 文件名还是 `.part` / `.!qB` / `.crdownload` 等临时后缀的，直接跳过

### 什么时候该关掉"文件变化实时触发"

监控目录在 **SMB / NFS 网络共享**上时，远端的变化不会通知给容器，inotify 收不到。
这时可以关掉它，只靠「下载器监控 + 每天定时扫描」。

## 挂载了目录 ≠ 会被监控

这一步很容易踩：compose 里 `- /volume1/media:/watch` 只是把目录**放进容器**，
助手并不会自动去扫它，必须在网页「设置 → 监控任务」里**加一条任务**告诉它：

| 任务名 | 本地监控目录 | 115 目标目录 | 启用 | 保留源文件 | CMS 通知 |
|---|---|---|---|---|---|
| 媒体库 | `/watch` | `/电影` | ☑ | ☐ | ☑ |
| 下载目录 | `/9kg` | `/下载` | ☑ | ☑ | ☐ |

点「浏览」会弹目录树，**顶部自动列出 compose 里挂进来的所有目录**（读 `/proc/self/mountinfo`），
点一下直接跳过去，不用一层层翻。输入框本身也带下拉候选，手敲时会提示这些挂载点。

想加一条任务时，直接点「+ 添加监控任务」，在「本地监控目录」上点浏览 → 点顶部那个 `/9kg` 就行。

两个任务级开关：

- **保留源文件**：勾上表示这个目录秒传成功后**不删本地文件**。下载目录建议勾上——文件还要做种、还要被 MoviePilot 整理，删了下游就断了。
- **CMS 通知**：勾上表示这个目录秒传成功后**通知 CMS 做增量同步**。下载目录一般**不勾**（`/9kg` 只是中转，真正入库的是 MP 整理后的 `/watch`），免得 CMS 反复扫到临时文件。

## 目录结构会原样搬到 115

监控目录里的子文件夹会被**原样创建**到 115 目标目录下，网盘已有同名文件夹则直接合并：

```
本地 /115                          115 目标目录 /电影
├── 蜘蛛侠/第一季/第一集.mkv   →    /电影/蜘蛛侠/第一季/第一集.mkv
├── 蜘蛛侠/第一季/第二集.mkv   →    /电影/蜘蛛侠/第一季/第二集.mkv
├── 蜘蛛侠/第二季/第一集.mkv   →    /电影/蜘蛛侠/第二季/第一集.mkv
└── root.nfo                   →    /电影/root.nfo
```

第二天本地又多了 `蜘蛛侠/第一季/第三集.mkv`，只会把这一集补进**已存在的** `/电影/蜘蛛侠/第一季/`，
不会重复建目录，也不会重复传已经成功的文件。

想让不同本地目录进不同网盘目录，就在「监控任务」里加多行；每个任务各自保持自己的目录结构。

## 工作流程

```
每 60 秒扫一次监控目录
      ↓
白名单扩展名 + 体积达标 + 已静置
      ↓
算 SHA1（全量）和前 128MB 的 SHA1（单遍 4MB 分块，不读两遍盘）
      ↓
POST /open/upload/init  →  status == 2 ?
      ├── 是 → 网盘文件已创建
      │        ├ 删除源文件开关开：删本地文件（空目录等每天定时清理）
      │        ├ 删除源文件开关关：保留本地文件
      │        ├ 企业微信通知
      │        └ CMS 增量同步
      └── 否 → 标记 held，等「下次每日扫描」再试
```

文件状态：

| 状态 | 含义 |
|---|---|
| `done` | 秒传成功（或网盘已有同名文件），不会重复处理 |
| `held` | 暂不能秒传，等待次日重试 |
| 无记录 | 还没处理过，或文件内容变了（重新下载） |

## 日志：出问题先看这里

所有关键动作都会记日志，**同时**输出到容器标准输出（`docker logs`）和文件：

| 位置 | 说明 |
|---|---|
| `/config/logs/app.log` | 当前日志（映射出来就是宿主机 `./config/logs/app.log`） |
| `/config/logs/app.log.1~3` | 历史日志，单个 5MB 自动轮转，最多保留 3 份 |
| 网页「日志」页 | 直接看最近 200~2000 行，支持关键字过滤、一键下载 |

记录的内容包括：

- 启动时的配置摘要（任务数、115 授权状态、日志路径）
- 网页登录成功/失败（**不记密码**）
- 设置保存（任务数、开关状态）
- 每个文件的处理结果：秒传成功 / 需真实上传 / 目录创建失败
- 触发来源：下载器完成、MP 整理、文件变化、每日扫描、手动
- 下载器轮询异常、路径没匹配到监控目录的原因
- 通知发送结果（企业微信、CMS）
- 外部触发（MP 推送）收到的路径数与跳过原因

排查时最有用的是按关键字过滤：

```
ERROR         只看错误
WARNING       只看警告（含"下载已完成但本地找不到"）
秒传成功       看成功的文件
外部触发       看 MP 推过来的记录
```

> 日志里不会出现 115 token、API Key、企业微信 secret、下载器密码。

## 数据与目录

| 路径 | 内容 |
|---|---|
| `/config/settings.json` | 所有设置（含企业微信 Secret，注意权限） |
| `/config/115_token.json` | 115 授权 token（refresh_token） |

容器里看到的 `/watch` 就是 compose 里挂载的宿主机目录。网页里「浏览」看到的是**容器内**目录树，所以你只能选到已经挂载进去的路径。

## 常见问题

**Q：一直显示"暂不能秒传"，是不是坏了？**
不是。秒传命中取决于 115 服务器上有没有完全相同的内容。新出的资源第一次基本都失败，等有人传过（或你自己传过），第二天重试就会命中。

**Q：能不能不能秒传就直接上传？**
本工具刻意不做真实上传——那样会吃掉你几十 G 上行带宽，也不是"秒传搬运"的意义。真要上传请用 115 官方客户端或 alist。

**Q：删了本地文件，目录还在。**
故意的。空目录统一由每天 `03:30` 的清理任务删除，避免边传边删目录导致扫描抖动。监控根目录永远不会被删。

**Q：网页打不开 / 二维码不出来。**
- 检查端口映射 `9191:9191`
- 二维码走 `passportapi.115.com` / `qrcodeapi.115.com`，容器要能访问外网
- 扫码状态接口是长轮询，二维码页面会显示"等待扫码…"，扫码后自动变成成功

**Q：换了 115 账号。**
网页右上角 **退出登录** → 重新扫码。

**Q：企业微信还要填 Token / EncodingAESKey 吗？**
不用。那两项是「接收」消息（回调）用的，本工具只往企业微信「发送」消息，只需要 企业ID / Secret / AgentId（和可选的代理地址）。

**Q：微信收到通知只显示"暂不支持此消息类型，请在企业微信中查看"？**
之前发的是 markdown 消息，微信端不渲染。现在已统一改成**纯文本**，微信、企业微信都能正常显示，
不需要任何额外配置（也不需要填 Token / EncodingAESKey，那两项是"接收消息回调"用的）。

**Q：企业微信报 60020（not allow to access from your ip）？**
你的服务器出口 IP 不在应用的可信 IP 里，且没配代理。两种解法：后台把 IP 加进「企业可信IP」，或者在设置里填「代理地址」。

**Q：上传目录有好几个，要装多个容器吗？**
不用。「设置 → 监控任务」里可以加任意多组「本地目录 → 115 目录」，
每个任务独立启停；界面和通知里都会标出任务名。

**Q：忘记网页密码了。**
删掉 `/config/auth.json` 再重启容器，就会恢复成 `admin / admin`：

```bash
docker compose exec u115-rapid rm -f /config/auth.json
docker compose restart
```

**Q：网页登录密码和 115 授权是一回事吗？**
不是。网页登录只是保护这个控制台；115 授权是扫码拿到的另一套 token，互不影响。右上角「退出登录」退的是网页，「退出 115 授权」才是清掉 115 的 token。

**Q：时间不对。**
设置 `TZ=Asia/Shanghai`。定时任务（次日重试、空目录清理）都按容器时区算。

## 构建与发行

### 用现成镜像（推荐）

```bash
docker compose pull && docker compose up -d
```

### 本地构建

```bash
git clone https://github.com/celestial520/115-rapid-upload
cd 115-rapid-upload
# compose 里注释掉 image、打开 build: .
docker compose up -d --build
```

改完代码重新构建：`docker compose up -d --build --force-recreate`

### 自动构建（GitHub Actions）

`.github/workflows/docker.yml` 已配好：推 `main` 或打 `v*` tag 会自动构建
`linux/amd64` + `linux/arm64` 并推到 `ghcr.io/celestial520/115-rapid-upload`。
也能在 Actions → build → Run workflow 手动触发。

## 关于 115 开放平台 client_id

扫码走的是 115 开放平台的设备码授权，需要一个开放平台应用的 `client_id`。
默认内置的是 MoviePilot 使用的那个 `client_id`；如果你自己在 [115 开放平台](https://open.115.com/) 申请了应用，可以在设置的「高级」里换成自己的。

token 只保存在你的 `/config/115_token.json`，不会发往任何第三方。
