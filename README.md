# 115秒传助手

监控本地目录，把文件**秒传**到 115 网盘：能秒传就秒传（不耗上传带宽），不能秒传时可选真实上传。

自带 WebUI（默认端口 `9191`）：扫码授权、多目录监控、状态查看、日志排查全在网页里完成。

---

## 功能

| 能力 | 说明 |
|---|---|
| 115 扫码登录 | 走 115 开放平台设备码授权，token 自动续期 |
| 秒传 | 只验证已有内容，不占上行带宽 |
| 真实上传 | 可选开关，不能秒传时走 OSS 分片上传 |
| 多任务监控 | 多组「本地目录 → 115 目录」，各自独立开关 |
| 保持目录结构 | 本地子目录原样建到 115，同名目录自动合并 |
| 三种触发 | 下载器完成通知 / 文件变化事件 / 每天定时扫描 |
| 整种子完成才处理 | 一个种子内还有文件没下完时，先跳过整个种子 |
| 通知 | 企业微信（纯文本）、CMS 增量同步、Muvyo 整理触发（后两者带 5 分钟合并间隔，可按任务关） |
| 日志 | 写文件并自动轮转，网页可看、可过滤、可下载 |
| 文件记录 | 按处理时间倒序分页展示（默认 30 条/页），成功会显示完成时间 |
| 深色模式 | 自动跟随系统，也可手动切白天/夜间 |

## 快速开始

### 1. docker-compose.yml

```yaml
services:
  u115-rapid:
    image: ghcr.io/celestial520/115-rapid-upload:latest
    # build: .                        # 想自己编译就注释掉上面这行、打开这行
    container_name: u115-rapid
    restart: unless-stopped
    ports:
      - "9191:9191"
    environment:
      TZ: Asia/Shanghai
      DATA_DIR: /config
    volumes:
      - ./config:/config
      - /volume1/media/已整理:/watch     # ← 改成你的媒体库目录（MP 整理后的）
      - /volume1/download:/9kg           # ← 改成你的下载目录（不需要可删）
```

### 2. 启动

```bash
mkdir -p /volume1/docker/115-rapid && cd /volume1/docker/115-rapid
# 把上面的 compose 存成 docker-compose.yml
docker compose up -d
```

打开 `http://你的NAS地址:9191`。

### 3. 登录

默认账号 **admin**，密码 **admin**。登录后到「设置 → 账号密码」改掉。

### 4. 配三件事

1. 右上角 **扫码登录 115**（手机 115 App 扫，二维码约 2 分钟有效）
2. **设置 → 监控任务** 加一条或多条：

   | 任务名 | 本地监控目录 | 115 目标目录 | 启用 | 保留 | CMS |
   |---|---|---|---|---|---|
   | 媒体库 | `/watch` | `/电影` | ☑ | ☐ | ☑ |
   | 下载 | `/9kg` | `/下载` | ☑ | ☑ | ☐ |

   「本地监控目录」点 **浏览**，弹窗顶部会自动列出 compose 挂进来的目录，点一下即可。
3. 保存 → 点 **立即运行一次** 验证链路

## 监控任务的三个勾选

- **保留**（保留源文件）：秒传成功后**不删本地文件**。下载目录建议勾上——文件还要做种、还要被 MP 整理，删了下游就断了。媒体库不勾，秒传完就删。
- **CMS**：秒传成功后**通知 CMS 做增量同步**。只有真正入库的目录才勾（比如 `/watch`）；下载目录一般**不勾**，免得 CMS 扫到中转文件。
- **MV**：秒传成功后**通知 Muvyo 触发目录监控整理**，让它生成 STRM。勾选逻辑和 CMS 一样；老配置没有这一项时，默认跟随 CMS 的勾选。

## 触发方式

不做周期性扫盘，只有三种触发：

| 优先级 | 触发 | 场景 |
|---|---|---|
| 1 | **下载器监控** | Transmission 任务完成，立即处理该种子的文件 |
| 2 | **文件变化事件**（inotify） | 目录里出现新文件（MP 整理移入、手动拷贝） |
| 3 | **每天定时扫描** | 兜底，默认每天 09:00 一次，也顺手重试上次失败的 |

三种触发都按**路径归属**分发：文件落在哪条任务的 `watch_dir` 里，就按那条任务的目标目录去秒传。所以任意监控目录都同时受三种触发覆盖。

MP 整理完成后把文件移进 `/watch`，靠的就是第 2 种（文件变化事件）——**不需要再装 MP 插件**。

### 种子内多个文件时，会等全部下完

一个种子里有多个文件（比如一部剧的若干集），只要还有文件在下，**整个种子都先跳过**——
哪怕其中几集已经下完，也不会先传，等全部下完再整批处理。

实现方式：轮询 Transmission 拿到还在下载的种子路径，这些路径下的文件一律不处理；
种子完成（`percentDone == 1`）时，才把整批文件一起交给秒传流程。

> 这个能力依赖「下载器监控」开着（它需要知道哪些种子还没下完）。
> 只靠 `.part` 后缀和每日扫描，无法判断同目录里其他文件是否还在下载。

### 正在写入的文件不会被误传

1. 下载器只认已完成任务
2. 文件事件和每日扫描会检查「文件写入静置」（默认 30 秒）+ 连续两次大小/时间一致
3. `.part` / `.!qB` / `.crdownload` / `.aria2` 等临时后缀直接跳过

### 路径映射：下载器里的路径 ≠ 容器里的路径

Transmission 报的是**它自己容器内**的路径，助手看到的是**另一个容器**的挂载，两者往往不一样。
例如 TR 报 `/media/下载/剧名`，而助手里这个目录挂在 `/9kg`：

| 下载器内路径 | 本容器路径 |
|---|---|
| `/media/下载` | `/9kg` |

在「设置 → 下载器监控 → 路径映射」加这一条即可。**只填目录前缀，不要带种子名**，长前缀优先匹配。

没配映射时日志会写：

```
[worker] 下载已完成但本地找不到：剧名 -> /media/下载/剧名
（下载器报 /media/下载/剧名；当前路径映射：未配置。
  到「设置 → 下载器监控 → 路径映射」添加 /media/下载 → /9kg）
```

设置页的「路径映射」下方会显示下载器最近一次报的完整路径，可以直接照着填前缀。

**兜底**：即使没配映射，助手也会拿种子名去各个监控目录里找同名文件/目录
（`/9kg/剧名`、`/9kg/下载/剧名`），找到就继续处理，并在页面上提示「建议补一条路径映射」。
同名目录只是应急，**正式部署还是建议配映射**，否则下载目录多套一层、或者多个目录同名时可能找不到。

### 什么时候该关掉「文件变化实时触发」

监控目录在 **SMB / NFS 网络共享**上时，远端变化不会通知给容器，inotify 收不到。
这时可以关掉它，只靠「下载器监控 + 每天定时扫描」。

## 目录结构会原样搬到 115

```
本地 /watch                        115 目标 /电影
├── 蜘蛛侠/第一季/第一集.mkv   →   /电影/蜘蛛侠/第一季/第一集.mkv
├── 蜘蛛侠/第一季/第二集.mkv   →   /电影/蜘蛛侠/第一季/第二集.mkv
└── 蜘蛛侠/第二季/第一集.mkv   →   /电影/蜘蛛侠/第二季/第一集.mkv
```

第二天本地又多一集，只会补进**已存在的** `/电影/蜘蛛侠/第一季/`，目录自动合并，不会重复建也不会重复传。

## 115 授权

「设置 → 高级 → client_id」默认用的是 MoviePilot 在 115 开放平台注册的公开应用，
所以手机扫码页会显示「MoviePilot」——**本工具不依赖 MP 运行**，MP 卸载也不影响已授权的 token。

想用自己的应用名：到 [open.115.com](https://open.115.com/) 申请应用，把 client_id 填进去，重新扫码。

### CMS

秒传成功后调用：

```
GET {CMS地址}/api/sync/lift_by_token?token={CMS_API_TOKEN}&type={lift_sync|auto_organize}
```

只有「勾了 CMS」的任务有成功文件时才会调用一次。CMS 需 0.3.5.11 以上（[文档](https://wiki.cmscc.cc)）。

### Muvyo

秒传成功后调用它的目录监控整理，让它扫到新文件、生成 STRM（[文档](https://muvyo.com/docs.html#api-key)）：

```
POST {Muvyo地址}/api/v1/monitor/trigger-organize
X-API-Key: {API_KEY}
  ?name={监控规则名}           # 填了规则名就用它，只调一次
  ?source_dir={任务的 115 目标目录}   # 没填规则名时按目录触发
```

| 配置 | 去哪拿 |
|---|---|
| 地址 | Muvyo 管理面板，默认 `http://IP:7811`（不要用独立媒体库端口） |
| API Key | 设置中心 → 配置 → 系统配置 → API Key，点「生成」再保存 |
| 监控规则名 | 目录监控页面上那条规则的名字，可选 |

**为什么建议填规则名**：同一个目录挂在两个 115 账号下时，只按目录分不出该整理哪个账号，
Muvyo 会直接报错。留空则用任务的「115 目标目录」当 `source_dir`，只在目录唯一时可用。

和 CMS 一样，每个任务可以单独勾「MV」决定要不要通知（升级后默认跟随 CMS 的勾选），
只有真的秒传/上传成功的文件才触发，失败或被拦截不会触发。填完可点「测试触发」验证。

**关于「未找到监控目录为 X 的规则」**：说明这个 115 目录在 Muvyo 里**没有建监控规则**。

- 「测试触发」只测**勾了 MV 的任务目录**（没勾的目录本来就不该触发，不会去打扰）
- 一次要触发多个目录时是**逐个触发**，某个目录没规则只跳过它，其它目录照常触发，
  按钮下面会直接写明「已触发：/待整理；/9kg 在 Muvyo 里没有监控规则，已跳过」
- 这类**配置问题不会每 5 分钟重试**（重试也不会好）：只在日志和「最近错误」里记一次。
  网络抖动、5xx 这种才排重试
- 想让它被整理，就在 Muvyo 里给这个目录加一条监控规则，或者干脆填「监控规则名」

### 触发间隔（防漏整理）

CMS 和 Muvyo 都是"扫目录"型接口，**短时间连续触发会互相打断，结果就是漏整理**。
所以两个通道各自有一个最小间隔，默认 **5 分钟**（设置 → 清理与通知 → 通知合并间隔，填 0 关闭）：

- 间隔内的触发**不会丢弃**，先攒着（`/config/notify_gate.json`）
- 到点自动合并补发一次：Muvyo 会把攒下的目录逐个触发（重复目录只发一次），CMS 补一次增量同步
- 发送失败也会留着，下个间隔再试，不会因为一次网络抖动丢掉整理（配置类错误除外，比如目录没规则、Key 不对，重试也没用）
- 状态页面会显示「已合并 N 次触发，约 X 分后补发」，日志里是 `[CMS]` / `[Muvyo]` 开头的合并/补发记录
- 「测试触发」「发送测试消息」不受间隔限制

> 企业微信消息不受这个间隔影响，每轮照样发——它只是消息，不会触发整理。

## 不能秒传时要不要真的上传

默认**只做秒传**，不能秒传就拦着等下次（不占上行带宽）。

打开「不能秒传时改为真实上传」后：

```
能秒传   → 秒传
不能秒传 → 走 115 的 OSS 分片上传，把文件真传上去
```

链路：`/open/upload/init` → `/open/upload/get_token`（STS）→ `/open/upload/resume` →
OSS `InitiateMultipart` → `UploadPart` → `Complete` + `x-oss-callback`。
分片最小 16MB、目标 96 片（2GB 约 32MB/片）。

> 一部 20GB 的电影会实打实占用 20GB 上行带宽。为了省带宽就保持关闭。

## 日志

| 位置 | 说明 |
|---|---|
| `/config/logs/app.log` | 当前日志（宿主机 `./config/logs/`） |
| `app.log.1~3` | 历史日志，单个 5MB 轮转，保留 3 份 |
| 网页「日志」页 | 看最近 200~2000 行，可过滤、可下载 |

记录内容：启动摘要、登录成败、设置保存、**每个文件的秒传成功/拦截/失败**、
触发来源、下载器轮询与未匹配原因、企业微信与 **CMS 通知结果**。

常用过滤关键字：`ERROR`、`WARNING`、`[秒传]`、`[CMS]`、`[通知]`。

> 日志不会记录 115 token、API Key、企业微信 secret、下载器密码。

## 常见问题

**Q：一直"暂不能秒传"是不是坏了？**
不是。秒传命中取决于 115 上有没有完全相同的内容。新资源第一次基本失败，等有人传过（或你自己传过），下次扫描就会命中。

**Q：MP 整理进 `/watch` 后要等多久？**
开了「文件变化实时触发」就是秒级（静置 30 秒后处理）；没开就等每天定时扫描。

**Q：下载目录里的文件被删了，影响做种吗？**
会。所以下载目录那条任务要勾「保留」。

**Q：`/9kg` 这种自定义挂载能被识别吗？**
能，但要手动加一条任务。挂载 ≠ 监控——compose 只是把目录放进容器，助手不会自动扫。

**Q：网页打不开 / 二维码不出来？**
检查端口映射；二维码依赖 `passportapi.115.com`、`qrcodeapi.115.com`，容器要能访问外网。

**Q：忘记网页密码了？**

```bash
docker compose exec u115-rapid rm -f /config/auth.json
docker compose restart
```

恢复成 `admin / admin`。

**Q：企业微信报 60020？**
服务器出口 IP 不在应用可信 IP 里。把 IP 加进后台白名单，或填代理地址。
